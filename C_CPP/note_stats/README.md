# note_stats：统计目录里的 Markdown 文件

一个小工具：递归遍历指定目录，把所有 `.md` 文件的路径打出来。

写它的起因很简单——Obsidian 仓库里的笔记散在好几层文件夹里，想知道「到底有多少篇、都在哪」，`ls` 不够用，`find` 又要记参数，索性自己写一个。

## 编译与运行

```bash
make            # 生成 note_stats
./note_stats ../data_struc
```

输出（每行一个文件路径）：

```text
data_struc/01-maxsubseq/思路与坑清单.md
data_struc/README.md
```

不传参数会给用法提示并返回 1：

```text
用法：note-stats <目录>
```

想看总数就接一个 `wc -l`：

```bash
./note_stats ../../ | wc -l
```

## 代码结构

整个程序只有 75 行，两个函数：

| 函数 | 职责 |
|---|---|
| `has_md_suffix(name)` | 判断文件名是不是以 `.md` 结尾 |
| `scan_dir(dirpath)` | 打开目录，逐项判断是文件夹还是普通文件，文件夹递归、`.md` 文件打印路径 |

几个值得看的点：

- **`has_md_suffix` 的指针算术**：`name + len - 3` 从首地址往后跳，正好落在最后三个字符上，再从那里 `strcmp` 到结尾。前面的 `len >= 3` 与 `&&` 短路是为了防越界——文件名比 `.md` 还短时直接判否，不去读内存。
- **`snprintf` 的返回值要检查**：返回的是「本来想写多长」，不是「实际写了多长」。所以 `n >= sizeof child` 说明路径被截断了，得跳过，否则后面 `stat` 一个残缺路径会得到莫名其妙的结果。
- **`stat` 而不是 `d_type`**：`readdir` 给的 `d_type` 在部分文件系统上不可靠，`stat` 多一次系统调用但结果确定。
- **错误只报告、不中断**：单个条目 `stat` 失败就 `perror` 一行继续扫，不因为一个坏链接放弃整个目录。

## 退出码

| 情况 | 退出码 |
|---|---|
| 正常跑完 | 0 |
| 顶层目录打不开（不存在 / 没权限） | 1 |
| 没给参数 | 1 |

注意：只有**顶层**目录打不开才会影响退出码，子目录里的错误只打印警告。

## 已知限制

- 只打印路径，不做汇总计数（需要的话接 `wc -l`）
- 路径缓冲区固定 1024 字节，超长路径会跳过并告警
- 不处理符号链接，递归深度也没设上限
- 只认 `.md`，不认 `.markdown`

这些都不影响日常用，真需要了再改。
