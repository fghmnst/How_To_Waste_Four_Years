# 最大子列和：思路与坑清单

陈越《数据结构》1.1-1.3 的练习笔记。代码在同目录 `1_` ~ `4_MaxSubseqSum.c`，`duibi.c` 是配套的计时练习。

这篇记的是**写之前想清楚的**和**写完踩到的**，不是代码解释——代码本身很短，直接读。

## 一、四种解法

| 文件 | 解法 | 复杂度 | 核心一句话 |
|---|---|---|---|
| `1_MaxSubseqSum.c` | 暴力穷举 | $O(n^3)$ | 枚举所有起点 `i` 和终点 `j`，再用一层循环把 `A[i..j]` 加起来 |
| `2_MaxSubseqSum.c` | 优化穷举 | $O(n^2)$ | 固定 `i`，让 `j` 一边右移一边累加，省掉求和那一层 |
| `3_MaxSubseqSum.c` | 分治 | $O(n\log n)$ | 答案要么在左半、要么在右半、要么跨中线，三者取最大 |
| `4_MaxSubseqSum.c` | 在线处理 | $O(n)$ | 扫一遍，前缀和一旦变负就丢掉重来 |

四份文件都是自带 `main` 的独立演示，数组写死，直接编译就能看结果。

## 二、正确性基准

改任何一份代码之前，先用这组用例对齐。约定是**允许空子列**，所以全负数答案取 0。

| 输入 | 期望输出 | 考什么 |
|---|---|---|
| `-2 1 -3 4 -1 2 1 -5 4 0` | 6 | 标准用例，最优块是 `4 -1 2 1` |
| `-1 5` | 5 | 抓 `1_MaxSubseqSum.c` 的 `k < j` |
| `-3 -1 -7` | 0 | 全负数，考「允许空子列」 |
| `1 2 3` | 6 | 全正数，答案取整个数组 |
| 单元素 `5` | 5 | 递归终止条件 |
| 单元素 `-5` | 0 | 同上，但走负数分支 |

## 三、故意保留的两个 bug

这两个没修，留作证据。想拿这四份代码做对拍，先把它们修掉。

### 1. `k < j` 少算了最后一个元素

```c
for (k = i; k < j; k++)   // ← 错，应该是 k <= j
    ThisSum += A[k];
```

内层求和实际覆盖的是 `A[i..j-1]`，而 `j` 最大到 `N-1`，所以 `A[N-1]` 永远不参与求和——等价于只对前 `N-1` 个数求最大子列和。

标准用例仍然返回 6，是因为最优块在下标 3~6，`j=7` 时就覆盖完了，最后一个 `0` 加不加不影响结果。bug 被用例掩盖了，换成 `{-1, 5}` 立刻暴露：返回 0，正确答案 5。

### 2. 函数名复制粘贴没改

`2_MaxSubseqSum.c` 里的函数还叫 `MaxSubseqSum1`。单文件跑没问题，但四个人把四份代码放进同一个头文件时会重定义，链接直接报 `multiple definition`。

## 四、分治的两个边界

- **终止条件**：`left == right` 时返回 `max(0, List[left])`。负数返回 0 不是笔误，是「允许空子列」这个约定落在递归最底层的写法。
- **`N <= 0` 必须单独挡掉**：否则会调 `DivideAndConquer(0, -1)`，`center` 算成负数，区间永远不收敛，递归停不下来。
- **跨中线为什么只扫两遍**：任何跨中线的子列，一定包含 `center` 或 `center+1` 这两个端点之一。所以从 `center` 向左累加、从 `center+1` 向右累加，各自取最大，拼起来就是跨中线的最优解。

## 五、计时实验（`duibi.c` 的思路）

测的是「多项式求值」两种写法的耗时：朴素 `pow` 版和秦九韶（Horner）版。结论看数量级就够，别拿绝对时间和课本比。

几个必须处理的坑：

| 坑 | 做法 |
|---|---|
| 重复次数固定 | 自适应：从 `K=1` 开始翻倍，直到总耗时落在 0.2~0.5 秒，再设上限防死循环 |
| 结果被编译器优化掉 | 累加到一个 `volatile` 变量里，保证调用真被执行 |
| `-O2` 把循环提出去 | 计时实验用 `-O0` 最省心 |
| 第一次调用是冷缓存 | 先跑一次不计时的 warm-up，或每档测 3 轮取中位数 |
| 整数除法得 0 | 写 `(double)(stop - start) / CLOCKS_PER_SEC / repeats` |
| `clock()` 和墙钟混淆 | `clock()` 是进程 CPU 时间，不是墙上走过的时间 |
| 重复次数溢出 | `K` 用 `long`，不要用 `int` |
| 每次输入都不同 | `srand(...)` 用固定种子，别用 `time(NULL)`，否则没法复现 |
| 把 `printf` 放进计时循环 | 测到的会主要是打印时间 |

规模选择：`N` 从 500 起步。`N=1000` 的 $O(n^3)$ 在 `-O0` 下可能接近 1 秒；做增长实验时 $O(n^3)$ 单独截断，让另外三种跑到更大的 `N`。

## 六、边界用例清单

写完之后至少各跑一次：

- 全负数
- 只有一个元素（正 / 负各一次）
- 只有一个正数，其余全负
- 最大值在开头 / 在结尾
- 数组里全是 0
- 空输入（`N=0`，只对 `PTA_1MSS.c` 和分治版有意义）

## 七、建议的验证顺序

1. 四个函数先过手工小用例，重点抓 `1_` 的 `k < j`。
2. 用同一组随机数组让四个函数互相对拍，结果一致才往下走。
3. 单独测一个算法，确认 ticks 不为 0、`K` 调整确实有效。
4. 跑完整对比表，检查 $O(n^3) \to O(n^2) \to O(n\log n) \to O(n)$ 是否依次明显下降。
5. 有余力再做 `N` 翻倍实验，验证增长率大致是 8 / 4 / 2 / 1。

## 术语小词典

| 术语 | 大白话 |
|---|---|
| 最大子列和 | 在一串数字里找一段**连续**区间，让这段的和最大；全负数时按「允许空子列」返回 0 |
| 暴力穷举 | 所有起点、终点都试一遍，慢但最好写 |
| 分治 | 从中间劈开，分别算左半、右半、跨中线，再取最大 |
| 在线处理 | 从左到右扫一遍，边扫边丢拖后腿的前缀，$O(n)$ |
| 秦九韶 / Horner | 把多项式改写成「一层层乘 x 再加系数」，少算很多次幂 |
| ticks | `clock()` 返回的时间单位，除以 `CLOCKS_PER_SEC` 才是秒 |
| 对拍 | 用同一组输入喂两个实现，结果不一致就说明至少有一个错 |
